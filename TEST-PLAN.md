# Тест-план: API PetStore

## 1. Объект тестирования
Публичное REST API интернет-магазина для питомцев (Swagger PetStore).  
Документация: https://petstore.swagger.io/

## 2. Цель тестирования
Проверить корректность работы API-эндпоинтов, обработку ошибок и соответствие документации.

## 3. Объём тестирования

### Что тестируем
- **Pet:** создание (POST), получение (GET), обновление (PUT), удаление (DELETE)
- Позитивные сценарии (валидные данные)
- Негативные сценарии (невалидные данные: отрицательный ID, несуществующий ID)

### Что НЕ тестируем
- Производительность и нагрузка
- Безопасность (авторизация)
- UI-интерфейс (только API)

## 4. Виды тестирования
- **Функциональное** — проверка корректности работы эндпоинтов
- **Негативное** — проверка обработки некорректных данных
- **Интеграционное** — цепочка запросов (создать → получить → обновить → удалить)

## 5. Инструменты
- Postman (ручное и автоматизированное тестирование)
- Newman (запуск из командной строки)

## 6. Критерии качества
- Все обязательные поля корректно обрабатываются
- API возвращает правильные HTTP-статусы
- Ошибки валидации возвращаются с понятными сообщениями
- Нет критических багов, блокирующих работу

## 7. Тест-данные
- Валидный питомец: `{"id": 888, "name": "TestDog", "status": "available"}`
- Негативные данные: отрицательный ID, отсутствие обязательных полей, невалидный статус
